# 固件完整性校验协议说明 (Firmware Integrity Protocol)
====================================================

1. 封装结构 (Packet Structure):
   - **FLAG**: 标志位 (4 Bytes) 
     * 固定为 `0xA5A55A5A`，用于 Bootloader 识别合法固件起始。
   - **CRC32**: 校验值 (4 Bytes) 
     * 基于 Data 区计算的 32 位循环冗余校验码。
   - **DATA**: 原始固件 (n Bytes) 
     * 经过 32-bit 对齐补齐后的二进制数据。

2. 生成算法 (Algorithm):
   - **对齐 (Padding)**: 
     * 原始 BIN 文件若非 4 字节整数倍，末尾自动补 `0x00`。
   - **多项式 (Polynomial)**: 
     * 使用 CRC-32 (MPEG-2) 标准：`0x04C11DB7`。
   - **硬件兼容性**: 
     * 完全匹配 STM32 硬件 CRC 单元默认配置（Initial: `0xFFFFFFFF`，无反转）。
   - **计算单位**: 
     * 以 32-bit Word (字) 为单位进行 XOR 运算。

3. 输出规范 (Storage & Manifest):
   - **存储路径**: 
     * 加工后的固件存放在 `bin/crc/` 目录下。
   - **字节序 (Endian)**: 
     * 采用小端序 (Little Endian) 存储 Header 及 CRC。
   - **元数据同步**: 
     * 脚本自动更新 `bin/manifest.json` 中的 `size` 与 `crc32` 字段。
   - **文件大小**: 
     * 最终大小 = 8 Bytes (Header) + 对齐后的 Data 大小。

4. 校验逻辑 (Verification):
   - **Step 1 (识别)**: 
     * 读取文件前 4 字节，比对是否匹配 `0xA5A55A5A`。
   - **Step 2 (计算)**: 
     * 从文件偏移 `0x08` 处开始读取数据，直至文件末尾，执行 CRC32 运算。
   - **Step 3 (比对)**: 
     * 将计算结果与文件偏移 `0x04` 处的 4 字节进行位比对。
   - **Step 4 (决策)**: 
     * 匹配则执行跳转/升级；不符则判定为固件损坏或非法篡改，停止加载。
